# API workspace

Independently authored V1 training candidate; normal source review and downstream qualification are pending. This lane is default off and does not change any existing dataset, reward objective, cost coefficient, budget, mask or group filter. The resource server is fully offline and mutates only its own fictional task state.

V1 contains 2,400 train tasks and 240 separately seeded validation tasks across 30 workflow families: five each for HR, CRM, accounting, storage, mail and chat. Every function has three fictional vendors. Each task connects two of those vendors and spreads relevant records across both. The vendors use different API prefixes, collection names and field aliases. Account discovery reports actual connection status; calling an unconnected account returns HTTP401 with a `WWW-Authenticate` header. Schema discovery never connects an account.

The four tools discover accounts, inspect vendor schemas, call a vendor API and batch independent requests. Requests specify method, exact path, query `params` and write `body` separately. A query string embedded in the path fails with HTTP400. Search/filter results paginate, and cursors are scoped to the vendor, collection and query. POST requires an idempotency key; replay returns the same object, while conflicting reuse returns409. PATCH and DELETE act on item paths. Amounts are integer cents. No operation reaches a real external account.

The system prompt explicitly gives the agent 50 model turns, encourages reasonable assumptions without clarification questions, requires discovery and persistence after401, and permits parallel independent requests. The stock `simple_agent` enforces `max_steps: 50`. `workspace_parallel` preserves result order and each individual status; dependencies belong in separate calls.

The tasks include onboarding, leave cover, ownership handoff, renewal arithmetic, territory reassignment, contact verification, payment reconciliation, expense thresholds, credit adjustments, file publication, redaction, indexes, message triage, deduplication, incident escalation and cross-store digests. Variants change task namespace, business values and boundary cases, record count, physical account placement, vendor dialects and distractors. The source contains no external task corpus, model-generated task text or benchmark-derived inputs. Names, addresses, documents and tools are authored in a `gw_` fictional namespace. `ROOT_SEED`, task IDs and source hashes define immutable V1 construction; a semantic change requires a new revision.

The server reconstructs initial state and goals from canonical task IDs. Callers cannot supply initial records, goals, rewards or grader scripts. Each native cookie owns one independent world; one resource worker owns that state. Reseeding restores deterministic state, close releases it, and old outstanding calls retain only the old detached world. Per-session atomic operations make concurrent calls safe. The server bounds active sessions and returns503 when capacity is exhausted.

Verification compares final persisted records against the immutable goal state. It checks changed fields, preserved records/fields, required new objects and required deletions; generated create IDs and action order do not affect grading. Extra records or unrelated changes fail. A textual success claim or fabricated action transcript earns nothing. Native verification closes its world after scoring; retrospective replay without state is unsupported. The RLTasks provider adapter projects this same score and closes through its existing lifecycle contract.

Prepare train/validation rows through RLTasks' existing `core.prepare.prepare` codec, using the hash-bound specs in `envs/api_workspace/spec/`. The prepared rows contain prompts, tools and canonical IDs; grader goals stay server-side. Five examples are committed for smoke tests. Bind a prepared train JSONL through the existing dataset-path override below; the default is those five examples. Local files need no registry credentials. Prepare the smoke input in a writable output directory: Gym writes dataset metrics next to the JSONL. This offline HTTP-only configuration sets the typed `ray_startup.enabled: false`; each component also declares that it does not require Ray. Other configurations keep the historical Ray startup default.

```bash
gym env test --resources-server api_workspace
gym eval run --config resources_servers/api_workspace/configs/api_workspace.yaml \
  --model-type vllm_model --split train --limit 5 --num-repeats 1 --concurrency 2 \
  --model-url "$POLICY_BASE_URL" --model "$POLICY_MODEL" \
  --output "$OUTPUT/rollouts.jsonl" --max-output-tokens 16384 --temperature 1.0 \
  "++api_workspace_agent.responses_api_agents.simple_agent.datasets=[{name:authored_train,type:train,jsonl_fpath:$API_WORKSPACE_DATA_JSONL,license:Apache\ 2.0}]"
```

Callers own model sampling, token/context budgets, endpoints and credentials. The quoted output-token setting is a smoke-test invocation, not a change to another lane. Native tests cover full-corpus gold/no-op/tamper state, HTTP401 recovery, strict paths/params, pagination/cursor scope, idempotency, concurrency, reset/close and the actual stock agent tool cycle. These source controls do not establish model success, transfer, training readiness or production adoption; real model rollouts must also be inspected before qualification.

The committed five-example CP146 smoke fixture contains one final-state success and four failures, all unmasked with no failure records. Agent/tool and verifier behavior was inspected: persistence repairs strict API errors, while wrong stores, filenames, extra writes and unrelated label changes remain failures despite textual completion claims. The example rollout fixture normalizes only model and input-path transport metadata; rewards and fictional task/tool traces are preserved. The original run had no model-call captures, so its native quality report leaves all five detailed health verdicts unobserved. This small sample establishes execution and inspection, not transfer, model quality, mixed-group yield or training readiness. Final cost binding and lane adoption belong to the selected native composition.
