The immutable generator bounds contain2,400 train identities and240 separately seeded validation identities across 30 workflow families: five each for HR, CRM, accounting, storage, mail and chat. Every function has three fictional vendors. Each task connects two of those vendors and spreads relevant records across both. The vendors use different API prefixes, collection names and field aliases. Account discovery reports actual connection status; calling an unconnected account returns HTTP401 with a `WWW-Authenticate` header. Schema discovery never connects an account.

The four offered tools search endpoint-catalog metadata, inspect vendor schemas, call a vendor API and batch independent requests. Catalog entries contain operation paths, fields and connection status, never task record contents or goals. Search/pagination selectors can be omitted. The account-list route remains available to existing direct API clients. Requests specify method, exact path, query `params` and write `body` separately. Containers accept objects or serialized JSON objects; omitted or JSON null containers are empty. Arrays, scalar JSON and Python `None` text produce recoverable validation errors without mutations. This supports nested JSON encoding without changing the native function-call grammar. A query string embedded in the path fails with HTTP400. Search/filter results paginate, and cursors are scoped to the vendor, collection and query. POST requires an idempotency key; replay returns the same object, while conflicting reuse returns409. PATCH and DELETE act on item paths. Amounts are integer cents. No operation reaches a real external account.

The system prompt states only the fictional workspace, the tool categories, the50-turn limit and final-state completion. Workflow facts and placement rules are in discoverable policy records; task surfaces vary which facts they state. The stock `simple_agent` enforces `max_steps: 50`. `workspace_parallel` preserves result order and each individual status; dependencies belong in separate calls.

The tasks include onboarding, leave cover, ownership handoff, renewal arithmetic, territory reassignment, contact verification, payment reconciliation, expense thresholds, credit adjustments, file publication, redaction, indexes, message triage, deduplication, incident escalation and cross-store digests. Variants change task namespace, business values and boundary cases, record count, physical account placement, vendor dialects and distractors. The source contains no external task corpus, model-generated task text or benchmark-derived inputs. Names, addresses, documents and tools are authored in a `gw_` fictional namespace. `ROOT_SEED`, task IDs and source hashes define immutable V3 construction; changes to constructed tasks or worlds require a new revision. Grader fixes are separately bound by the locked engine source hash and invalidate earlier source qualification.

The server reconstructs initial state and goals from canonical task IDs. Callers cannot supply initial records, goals, rewards or grader scripts. Each native cookie owns one independent world; one resource worker owns that state. Reseeding restores deterministic state, close releases it, and old outstanding calls retain only the old detached world. Per-session atomic operations make concurrent calls safe. The server bounds active sessions and returns503 when capacity is exhausted.

Verification compares final persisted records against the immutable goal state. It checks changed fields, preserved records/fields, required new objects and required deletions; generated create IDs and action order do not affect grading. Created text-file contents allow LF/CRLF line endings and one terminal newline; other content, fields and preserved records remain exact. Extra records or unrelated changes fail. A textual success claim or fabricated action transcript earns nothing. Native verification closes its world after scoring; retrospective replay without state is unsupported. The RLTasks provider adapter projects this same score and closes through its existing lifecycle contract.
